# 用个人微信给 Claude 派活（cc-connect）

[English](wechat-remote.md) · 中文

人在外面、逛街的时候，用手机微信给家里电脑上的 Claude Code 发任务、看汇报。Claude 照常当经理派活，工人照常在电脑上跑。

依据：一个真实生产项目，2026-10-02 起每天在用，到 10-12 共 10 天。只在 macOS 上用过。

## 原理

[cc-connect](https://github.com/chenhg5/cc-connect)（开源）常驻在你的电脑上，把个人微信收到的消息转给本机的 Claude Code **命令行版**，再把回复发回微信。所以电脑要一直开着、不能休眠。

它拉起的是命令行版，和桌面版对话互不相通：两边靠项目里的状态文件（交接文档、`_tickets/queue.md`、`_receipts/progress.md`）同步，不靠对话记忆。

## 装好

以 cc-connect 自己的说明和 `cc-connect --help` 为准，下面只列顺序和踩过的坑。

1. 按 cc-connect 官方 INSTALL.md 安装。
2. `cc-connect weixin setup` 扫码绑定个人微信。只允许你自己的号发指令（配置里的 `allow_from`）。
3. `cc-connect config example` 看完整示例，在配置文件里建一个项目：agent 用 Claude Code，`work_dir` 指到**项目根目录**。开在别的目录，Claude 就读不到项目规则。项目只配一个最省事，配多个在微信里容易发错。
4. Claude Code 命令行版要单独登录一次。没登录时微信只会收到 “Not logged in”，后面的消息都排队卡住；登录后执行 `cc-connect daemon restart`。
5. `cc-connect daemon install` 装成后台服务，开机自启。改了配置或卡住时，`cc-connect daemon restart`。
6. 在中国大陆直连 Anthropic 接口会被拒（403）：要在后台服务的环境变量里配代理（例如 `HTTPS_PROXY`），在终端里手动登录时也要带上代理。
7. 微信那头点不了确认弹窗，命令行版通常要设成免确认才能跑完一单。这等于允许 Claude 在这个项目里不经确认就动手，先想清楚；随时可以在微信里发 `/mode default` 改回逐项确认。
8. 生成的页面、截图可以用 `cc-connect send` 发回微信（参数以 `--help` 为准），手机上直接看。

## 缓存：最容易白花额度的地方

Claude 的提示缓存，订阅用户在没超额时约 1 小时，超额后约 5 分钟。微信对话往往一开就是一整天，上下文动辄几十万 token。隔了 1 小时以上再说话，整段对话要按原价重读一遍。

实测：Claude 在长对话里给自己定了一个第二天早上 8:30 的“早报”提醒，一响就把隔夜的整段对话唤醒，一下用掉了 5 小时额度的约 20%。

所以：

- **长时间离开前压缩**：睡觉、出门很久之前，在微信里发 `/compact`。第二天就算缓存过期，要重读的内容也少得多。状态都在文件里，压缩不丢事。
- **不要让 Claude 在长对话里定隔夜的提醒或早报**。第二天你自己来问。把这条写进你的全局规则，它就不会自作主张。
- **真要定时跑的事，开新会话跑**：cc-connect 的定时任务**默认复用原会话**，正好会去唤醒那个长对话。建定时任务时一定加 `--session-mode new-per-run`（例如 `cc-connect cron add --cron "30 9 * * *" --prompt "…" --session-mode new-per-run`），或者用桌面版的定时任务。让它只读状态文件。
- **不用每 55 分钟发一条消息“保温”**：每发一次也要按缓存价读一遍整段对话，一晚上 8 小时大约 9 次，加起来跟原价重读一遍差不多，省不了什么。只有你确定一两个小时内就回来时，保温才划算。
- **在 1 小时内来回说话，缓存一直是活的**，不用特意做什么。
- 同一个对话里别中途换模型、别开关快速模式、别增减连接器，这些也会让缓存作废、整段重读。

## 用起来

- 手机上看，回复要短：在规则里写“手机上读，大白话，先说结果”。
- 问进度时让它回拓扑图（见 SKILL 第四节），截图发回微信，比一大段文字好看。
- 派活和等结果照常由工人在电脑上跑，不占你的 Claude 额度；Claude 只花额度在拆活、验收和拍板上。
- 连接程序重启时，正在发的那条消息可能丢；发出去几分钟没反应，就再发一次或执行 `cc-connect daemon restart`。
